# Карта функционального паритета Qidi Admin Studio

Этот файл определяет, что считается полным объединением: Windows-приложение
сохраняет нативные вкладки OrcaSlicer **Подготовка** и **Просмотр**, а функции
Qidi Admin App становятся частью того же приложения и используют один
Raspberry Qidi Admin Server. Android остаётся отдельным клиентом тех же API.

| Возможность Qidi Admin App | Серверный интерфейс | Нативное место в Qidi Admin Studio | Состояние |
| --- | --- | --- | --- |
| Подключение, HTTPS, API-ключ | `/api/v1/status` | `Qidi Admin` → настройки подключения | реализовано |
| Защищённое хранение ключа | Windows Credential Manager | общие настройки и Print Host fallback | реализовано |
| Температуры, состояние, процент, время | `/api/v1/status` | виджет Admin / строка состояния | базовая реализация |
| Камера и снимок | `/api/v1/camera/snapshot` | виджет Admin | базовая реализация |
| Непрерывное видео | `/api/v1/camera/stream` | виджет Admin | нативный MJPEG-приёмник, требуется CI-проверка |
| Пауза, продолжение, E-stop, G-code | `/api/v1/command-queue` | быстрые действия и терминал Admin | реализовано |
| Очередь: приоритет, отмена, повтор | `/api/v1/command-queue` | список очереди Admin | базовая реализация |
| Макросы | `/api/v1/macros` | селектор макросов Admin | базовая реализация |
| Материалы и остатки | `/api/v1/materials/spools` | карточка материалов / будущая боковая панель | базовая реализация |
| Обслуживание | `/api/v1/maintenance/tasks` | карточка обслуживания / будущая панель | базовая реализация |
| Предпечатная проверка | `/api/v1/printer/preflight` | перед запуском печати из Print Host | реализовано на серверном старте |
| Отправка G-code и запуск печати | `/api/v1/files/upload`, `/api/v1/printer/start` | обычный диалог отправки Orca | реализовано |
| История, экспорт CSV/JSON | `/api/v1/history` | будущая вкладка Admin: журнал | требуется UI |
| Каталог катушек, QR | `/api/v1/materials/*` | будущая вкладка материалов | требуется UI |
| Аналитика печати | `/api/v1/reports/*` | будущая вкладка Insights | требуется UI |
| Помощники: материал, диагностика, калибровка | безопасные G-code/API | будущие мастера Admin | требуется UI |
| Конфигурация Klipper и резервные копии | `/api/v1/config/*` | будущая вкладка Advanced | требуется UI |
| Здоровье Raspberry/туннелей | `/api/v1/health/*` | будущая страница Server Health | требуется UI |
| Push/уведомления Windows | события сервера/WebSocket | уведомления/трей | требуется нативный transport |

## Инварианты

1. Слайсинг, подготовка модели и послойный просмотр остаются кодом OrcaSlicer,
   а не веб-вставкой и не упрощённой копией.
2. Любая управляющая команда проходит через Qidi Admin Server и получает
   идентификатор, состояние и результат в очереди.
3. Секреты не попадают в `.3mf`, пресеты, журналы, экспорт или URL.
4. Windows и Android используют одинаковые серверные модели данных; расхождение
   допускается только в нативном представлении интерфейса.
5. Печать из Orca сначала загружает файл на Raspberry, затем сервер выполняет
   собственную проверку перед запуском.

## Ближайший порядок переноса

1. Завершить проверяемую Windows-сборку базовой интеграции и ребрендинга.
2. Проверить MJPEG-приёмник с автоматическим переподключением и диагностикой потока.
3. Вынести журнал и серверную очередь в полноценную нативную страницу Admin.
4. Перенести мастера материалов, предпечатной проверки и обслуживания.
5. Добавить WebSocket-события, уведомления и панель состояния Raspberry.
